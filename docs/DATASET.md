The dataset README says the set combines human-collected and generated images, and that *"missing-PPE labels refer to visible body regions; occlusion alone is not evidence of missing equipment."* The compliance rules follow this statement (see ARCHITECTURE.md §3).

## 2. Location and preservation

The original dataset is at `~/Desktop/471 Project/construction-ppe/` and is treated as **read-only**:

- A SHA-256 checksum of every file was taken before any work started: `data/dataset_baseline.sha256`, 2,004 files, with `.DS_Store` files excluded.
- Training reads from `data/dataset_mirror/`, which contains symbolic links to the original files. Ultralytics writes its label cache files (`labels/train.cache`, `labels/val.cache`) into the mirror, not into the original folder.
- To verify the dataset is unchanged, run from the `471 Project` folder:

  ```bash
  shasum -a 256 -c SiteGuard-AI/data/dataset_baseline.sha256 | grep -v ': OK$'
  ```

  No output means every file is unchanged.

## 3. Configuration

The original `data.yaml` uses `path: construction-ppe`. That is a relative path, which Ultralytics resolves against the current directory or its global `DATASETS_DIR`, so it fails from other folders. SiteGuard uses three files instead:

| File | Purpose |
|---|---|
| `configs/dataset.yaml` | Hand-written. Holds the source path *relative to the SiteGuard-AI folder* (`../construction-ppe`), the mirror location and the 12 class names. |
| `data/generated/dataset_resolved.yaml` | Generated by `python -m src.utils.dataset_tools`. Absolute `path` pointing at the mirror. Used for training and evaluation. |
| `data/generated/viewpoint/*.yaml` | Generated by `python -m src.evaluation.viewpoint_evaluation prepare`. Used for the viewpoint experiment. |

The environment variable `SITEGUARD_DATASET_DIR` overrides the dataset location, for example on another computer.

## 6. Image groups and viewpoints

Filenames fall into two groups:

| Prefix | Train | Val | Observed content |
|---|---:|---:|---|
| `source-*` | 234 | 59 | Wide site scenes: warehouses, excavations and building shells. Most are taken from elevated CCTV or drone positions, often with fisheye "doorway camera" framing. Workers are small. |
| `ultralytics-ppe-nov2026-*` | 566 | 141 | Close-up and medium shots of 1–3 workers at eye level. |

The dataset does **not** document camera angles. To support the viewpoint experiment, every one of the 1,000 images was labelled by visual inspection:

1. `scripts/make_contact_sheets.py` produced numbered thumbnail sheets: 30 per sheet for scene images, and 48 per sheet for close-ups.
2. Each sheet was inspected and a code written into `data/viewpoint_sheets/codes.txt`: **F** frontal / eye-level camera, **S** side or rear view at eye level, **O** elevated / overhead (camera clearly above the workers), **L** low angle (camera below), **U** unclear / no workers.
3. `scripts/build_viewpoint_metadata.py` converts the codes into `data/viewpoint_metadata.csv`. The columns are filename, source split, viewpoint, image group and labelling method.

**Limitations of these labels**

- They were assigned by an AI assistant (Claude) viewing small thumbnails, not by a domain expert. Borderline cases are subjective, for example a slightly elevated camera, or a three-quarter view versus a side view. The student should spot-check them, especially the `side` labels.
- A label describes the dominant viewpoint of the whole image. Workers within one image can face different ways.
- Viewpoint is **confounded with image group**. Almost all frontal images are close-ups (large workers), while almost all overhead images are wide scenes (small workers). A drop in accuracy on overhead images can therefore come from smaller objects, a different image source or style, *or* the viewpoint itself. The overhead comparison cannot separate these causes. Only 7 val images are wide-scene frontal shots, which is too few for a controlled comparison. The **side** group is different: 112 of its 116 images are close-ups, so *frontal close-up vs side close-up* compares viewpoint within the same image style. This is the most controlled comparison the dataset allows.
